# Implementation Plan: Slice 6 — Content, CMS & SEO

**Branch**: `007-content-seo` | **Date**: 2026-10-19 | **Spec**: [spec.md](spec.md)

## Summary

Replace the placeholder home with a server-rendered, CMS-driven home (published `ContentVersion`), add the admin «محرر الموقع» (sections, autosaved draft, desktop/mobile preview, publish, discard with undo, version history and restore) following the prototype, content pages and a `/traders` page, a buying-guides blog, the «ساعدني أختار» quiz, and the SEO layer: per-page meta + canonical + hreflang, sitemap, robots, structured data (`LocalBusiness`, `BreadcrumbList`, `Article`, existing `Product`/`Offer`/`AggregateRating`) and the Google Merchant feed. The tables (`content_versions`, `pages`, `guides`, `quiz_rules`, `settings`) and the `content.manage` permission already exist; the only schema change is `guides.summary`.

## Technical Context

**Language/Version**: TypeScript (strict), Node 24
**Primary Dependencies**: Nuxt 4, @nuxtjs/i18n, shadcn-vue, Tailwind 4; NestJS 12, Prisma 7; Zod 4 in `@serag/shared`. **New**: `sanitize-html` (+ types) in `apps/api` for server-side rich-text sanitizing; TipTap (`@tiptap/vue-3`, `@tiptap/pm`, `@tiptap/starter-kit`, `@tiptap/extension-link`, `@tiptap/extension-image`) in `apps/web`, admin-only and lazy-loaded so storefront chunks stay unchanged. Claude installs them before delegating (implementers have no shell).
**Storage**: PostgreSQL. Home = rows in `content_versions` (`page = 'home'`): one `published` row is current; one `draft` row is the working copy; publishing inserts a new `published` row (history) and keeps the newest 20 per page. `guides.summary` added by migration. Quiz definition stays in `quiz_rules.questions` / `.rules` JSON validated by Zod on read and write.
**Testing**: Vitest unit (shared schemas, sanitizer, quiz scoring, canonical/sitemap helpers), API e2e (`apps/api/test`), TesterArmy browser e2e (`tests/e2e`).
**Performance Goals**: home = one published-content query + the existing flash/guides/category queries, SSR with short SWR cache; sitemap and feed generated by the API, cached ≤ 1 h by Nuxt `routeRules` (`swr: 3600`); storefront bundles must not grow with editor or Zod code (Slice 3 perf rule).
**Constraints**: rich text sanitized on save (allowlist) and rendered with `v-html` only from sanitized API output; fail-closed admin permissions + CSRF + audit; public endpoints return published data only; store content Arabic-only (UI strings ar + en); logical CSS; 320 px.

## Complexity Tracking

| Addition | Why needed | Simpler alternative rejected because |
|---|---|---|
| `sanitize-html` (API) | Pages and guides store rich text that the storefront renders as HTML; it must be sanitized against an allowlist on the server | Regex stripping is unsafe; a hand-written parser is riskier than a maintained library |
| TipTap (web, admin only) | PRD US-11.2 asks for a rich-text editor; TipTap gives a controlled schema matching the sanitizer allowlist | `contenteditable` by hand produces arbitrary markup; Markdown would need a renderer on the storefront and is unfamiliar to the store owner |
